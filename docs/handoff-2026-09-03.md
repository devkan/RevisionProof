## 현재 제품 흐름과 한계

1. 사용자 피드백을 Gemini가 실행 가능 / 추가 설명 필요 / 편집자 필요로 분리한다.
2. 사용자가 실행 가능한 요청을 체크한다. 지원하지 않는 요청은 상태와 이유를 보여주며 실행하지 않는다.
3. 증거에 연결된 제한적 PUNCH_IN의 A/B 미리보기를 만든다.
4. B 등 한 안을 선택하면 **앱이 전체 원본 영상을 수정하여 생성**하고 자동 검증한다. 별도 편집 MP4 업로드는 선택적 경로이며 기본 흐름의 필수 단계가 아니다.
5. Change Map에서 변경 구간을 확인하고 원본/수정본을 큰 레이어 팝업으로 동시 재생·탐색한다.
6. 최종 전달 승인은 사용자가 직접 한다. 과거 편집을 메모리에 저장하려면 그 승인과 별도의 명시적 저장이 모두 필요하다.

제약과 표현상 주의:

- 현재는 시드된 데모 자산에 대한 제한적 편집 흐름이다. 임의 영상 업로드→자동 전사/색인→범용 편집 제품으로 설명하지 않는다.
- 샘플은 30초짜리 시각적 4장면 스토리보드와 합성 톤이다. 발화/장면 메타데이터는 작성된 시드이며 실제 발표자를 자동 전사한 결과가 아니다.
- 외부 수정본 업로드 기본 제한: **24 MiB, 60초 이하, 정확히 1280×720, MP4/H.264/AAC**. 기준 코드는 `backend/src/revisionproof/settings.py`, `media/probe.py`이다.
- 현재 안전 편집 계약은 한 요청의 4–8초 PUNCH_IN이고 기본 요청은 6초다. 임의 B-roll 생성이나 모호한 “더 역동적으로”를 자동 처리한다고 주장하지 않는다.
- Change Map은 초당 2회 샘플링 진단이다. 모든 프레임 무결성을 보장하지 않고 frozen spec의 세 검사를 대체하지 않는다.
- HNSW/QBit 선택 UI가 있다고 해당 엔진이 실행됐다는 뜻은 아니다. 빈 라이브러리는 count만 실행하며, 작은 집합/조건에서는 exact가 정상이다. 실제 사용 엔진과 EXPLAIN 증거를 구분한다.
- 현재 run 저장소는 프로세스 메모리다. 새로고침하면 활성 run UI가 복원되지 않고 재시작/재배포 시 기존 run API도 사라질 수 있다. GCS 영상·ClickHouse 증거의 보존과 run 복원은 별개다.

현재 동작은 의도적인 `memory_save_policy=read_only`이며 실패가 아니다. 다음은 **별도 소유자 승인 후** 진행할 작업이다.
