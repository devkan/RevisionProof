## 2. Priority Items: Browser QA Reproduction & Findings

### Item B: "Compare this moment" Disabled on Failed External Verification

- **Status**: **CONFIRMED & REPRODUCED IN STAGING BROWSER (재현 완료)**
- **Judgment**: **Defect (결함 - 연동 누락)**
- **Execution Environment**: Live Staging (`https://revisionproof-staging-sdixpvvwoq-uc.a.run.app/studio`), Chromium headless 1280×900
- **Evidence Files**:
  - **Screenshot**: [docs/evidence-issue-b-browser-reproduction.png](evidence-issue-b-browser-reproduction.png)
  - **Recording**: [docs/qa-recordings/issue-b-and-c-staging-browser-reproduction.webm](qa-recordings/issue-b-and-c-staging-browser-reproduction.webm)

#### Reproduction Steps
1. Navigate to `https://revisionproof-staging-sdixpvvwoq-uc.a.run.app/studio`.
2. Upload source video (`kanapp_promo_english_editable_30s.mp4`), advance to Step 2 (Edits).
3. Apply `Promo highlight` template (Zoom + Text overlays), advance through Step 3 (Plan), and generate previews in Step 4 (Compare).
4. Select Version B and proceed to Step 5 (05 · CHECK).
5. In Step 5, click **"Check an external edit"** and upload the unedited 30s source file as an external candidate.
6. Automated verification executes on Cloud Run:
   - Result: `BLOCKED · 1 of 3 checks pass` (`APPROVED_PATCH_MISMATCH` failure).
   - Banner: `Download is blocked. At least one required check failed.`
   - Change Map appears indicating: `6 seconds to review` (windows 0:04 to 0:09 marked with warning triangles).
7. Click on the first warning window (`0:04–0:05 · Review needed`).
8. Observe the **"Compare this moment"** button.

#### Expected vs. Actual Behavior
- **Expected Behavior**: "Compare this moment" button must be enabled using the uploaded file's local blob URL (`checkedVideo`), allowing the creator to inspect where and why the edit failed side-by-side with the original video.
- **Actual Behavior**:
  - The "Compare this moment" button is **disabled** (`disabled=""`).
  - Browser console/DOM check: `button.isDisabled() === true`.
- **Root Cause Code**:
  - In `frontend/src/RevisionIntelligence.tsx:41`:
    `<button type="button" className="secondary-button" disabled={!run.generated_version_url} onClick={() => setComparing(true)}>`
  - In `frontend/src/StudioApp.tsx:680`:
    `<ChangeMap run={run} />` — `StudioApp` tracked the uploaded blob URL in `checkedVideo` but never passed it to `ChangeMap`. Because the backend intentionally returns `generated_version_url = None` for externally verified files, the button unconditionally disables.

### Item C: Change Map Retains Stale Failure Explanation After BLOCKED → PASS

- **Status**: **CONFIRMED & REPRODUCED IN STAGING BROWSER (재현 완료)**
- **Judgment**: **Defect (결함 - React 상태 동기화 누락)**
- **Execution Environment**: Live Staging (`https://revisionproof-staging-sdixpvvwoq-uc.a.run.app/studio`), Chromium headless 1280×900
- **Evidence Files**:
  - **Screenshot**: [docs/evidence-issue-c-browser-reproduction.png](evidence-issue-c-browser-reproduction.png)
  - **Recording**: [docs/qa-recordings/issue-b-and-c-staging-browser-reproduction.webm](qa-recordings/issue-b-and-c-staging-browser-reproduction.webm)

#### Reproduction Steps
1. Following the Issue B reproduction above, keep the `0:04–0:05 · Review needed` window selected on the timeline.
2. In the action bar, click **"Run checks again"** (which instructs Cloud Run to render and verify the approved Version B plan).
3. Automated verification finishes:
   - Left progress updates to: `Full check: PASS`.
   - Banner updates to: `PASS · 3 of 3 checks pass` / `Continue to approval >`.
   - Change Map summary updates to: `No sampled review flags` (green checkmark).
   - Timeline windows all switch to blue (`Requested edit`) or gray (`Unchanged`). Zero warning windows remain.
4. Observe the Change Map detail box below the timeline **without clicking any other window**.

#### Expected vs. Actual Behavior
- **Expected Behavior**: With no review flags remaining, the detail box should immediately refresh to show the new PASS state (defaulting to the first window or the requested edit window), stating `No sampled review flags` or `These samples match the expected kept scenes.`
- **Actual Behavior**:
  - The detail box still blatantly displays the stale failure explanation from the prior BLOCKED run:
    ```text
    0:04–0:05 · Review needed
    The observed result differs from the approved edit, protected video content, or audio. Watch this moment.
    ```
  - Even though the timeline above shows `No sampled review flags` and check verdict is `PASS`, the detail text remains frozen on the stale failure until another window is clicked manually.
- **Root Cause Code**:
  - In `frontend/src/RevisionIntelligence.tsx:15, 18`:
    ```tsx
    const [selected, setSelected] = useState<ChangeWindow | null>(null)
    ...
    const active = selected ?? map.windows.find((w) => w.status === 'review') ?? map.windows.find((w) => w.requested) ?? map.windows[0]
    ```
  - In `frontend/src/StudioApp.tsx:680`:
    `<ChangeMap run={run} />` lacks a `key` prop. When `run` updates from BLOCKED to PASS, the component is re-rendered rather than remounted. `selected` retains the stale object reference from the old `map.windows`, bypassing the new `map.windows` search.
