## Outcome

The existing UI is preserved at `/`. A separate production React screen is available at `/studio` (and, for compatibility, `/?ui=studio`). It recreates the reference layout and progressive workflow without copying the HTML prototype or replacing the existing app.

The new flow is:

1. Source
2. Revisions
3. Plan
4. A/B
5. Verify
6. Approve

Desktop uses the reference's fixed header, six-step bar, independently scrolling left/center/right workspace and bottom action bar. Below 940 px it becomes a single-column responsive layout; no feature is removed.

## Functional mapping

- Source: sample or MP4/MOV/WebM upload, browser validation, file metadata, replacement and large preview.
- Revisions: all eight current operations, one open settings form, editable timing, smart scene finder, natural-language draft, six quick starts, mixed-language speech transcription and logo upload.
- Plan: exact operations and warnings, explicit selection of detected quiet-pause cuts, duration estimate and original-timeline seek.
- A/B: current backend candidate semantics are preserved. A/B compares complete plan variants rather than inventing unsupported per-item backend decisions.
- Verify: existing `RevisionSpec`, automatic full-video render, three deterministic checks, Change Map and optional external MP4 verification.
- Approve: explicit human delivery approval and download, followed by the existing capability-gated approved edit memory control.
- Approved revisions: the header side view reuses request-scoped Edit Memory. Read-only or no-active-request states do not show a misleading global search box.
- Proof trace: upload, interpretation, scene search, processing, deterministic verification and final human approval remain separated. A LIVE badge is never used as proof by itself.

## Existing sample issue found during E2E

The first Studio E2E reached A/B but full verification failed at `could not decode frame at 24.250s`. The UI was calling the same existing endpoints correctly. Root cause was the bundled demo generator producing 24 fps while `editing/sampling.py` and uploaded-source preparation use a canonical 30 fps frame timeline. After changing only the demo generator to 30 fps and regenerating ignored local demo media, the same flow passed.
