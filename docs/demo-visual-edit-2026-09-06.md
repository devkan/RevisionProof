38개 컷을 사용했다. 긴 렌더링 대기와 반복 조작을 제거했고, 일부 조작 구간만 1.4–2배속으로 압축했다. 핵심 설정과 결과는 주로 정상 속도로 유지했다. 주요 장면에 화면 확대·이동을 적용했으며, 일부 설정 장면은 같은 녹화 프레임의 미리보기와 설정 패널을 나란히 배치했다. SQL 장면은 같은 프레임의 쿼리와 6개 결과 행을 배치해 편집기의 빈 공간을 줄였다. 새로운 UI 값이나 PASS/FAIL 상태를 만들어 넣지 않았다.

## 확인 범위

- FFprobe로 길이·프레임 수·해상도·코덱·스트림 구성을 확인했다.
- 최종 파일 전체를 FFmpeg `-xerror`로 디코딩했고 오류 없이 완료됐다.
- 전체 컷 대표 프레임과 주요 설정·검증·SQL 화면의 원본 크기 프레임을 확인하고 구도를 수정했다.
- `demo_trial_5.mp4`에는 실제 녹화된 Query history 및 `version_checks` SELECT 결과가 있다. 이 세션에서 클라우드 쿼리를 다시 실행한 것은 아니다.
- 잘못된 외부 파일에 대한 FAIL과 앱이 선택한 B를 새로 만들어 얻은 PASS를 순서대로 보여준다. 잘못된 파일 자체가 수정됐다고 표현하지 않는다.
- 마지막 화면은 승인 대기다. 다운로드 승인·메모리 저장·게시·제출을 수행하지 않았다.
